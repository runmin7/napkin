# 빠른 메모

트레이에 상주하는 자동저장 메모장. Windows + Electron.

적어 두고 싶은 것이 생겼을 때 `Ctrl+Alt+M` 한 번으로 창을 띄우고, 다 쓰면 그대로 닫는다.
저장 버튼이 없다 — 글을 멈추면 알아서 저장되고, 창을 닫거나 다른 프로그램으로 넘어갈 때도 저장된다.

메모는 끝까지 **`.txt` 평문**이다. 전용 포맷도, 데이터베이스도 쓰지 않는다.
이 앱을 지워도 메모는 윈도우 메모장으로 그대로 열린다.

## 무엇을 할 수 있나

- **자동 저장** — 입력이 멈추고 0.6초 뒤, 창이 포커스를 잃을 때, 다른 메모로 넘어갈 때, 앱이 꺼질 때
- **목록 패널** — 창 오른쪽에 늘 붙어 있다. 검색, 즐겨찾기, 삭제, 우클릭 메뉴
- **마크다운** — 편집 화면은 기호를 글자 그대로 두고 색으로만 구분한다. `view` 버튼을 누르면 같은 자리에서 꾸민 모습으로 바뀐다
- **조회 전용** — 다 쓰고 읽기만 하는 메모는 목록에서 우클릭 → `열 때 조회 전용으로`. 다음부터 열면 꾸민 모습으로 나온다. 잠그는 것이 아니라 여는 순간의 기본값이다
- **메모별 단축키** — 자주 쓰는 메모에 조합을 걸면 어디서나 그 메모가 바로 열린다
- **저장 실패를 숨기지 않는다** — 저장이 안 되고 있으면 상태바와 대화상자로 알리고, 그대로 나가려 하면 한 번 붙잡는다

## 단축키

| | | |
|---|---|---|
| 창 보이기 / 숨기기 | `Ctrl+Alt+M` | 어디서나 |
| 새 메모 | `Ctrl+N` | 메모창 |
| 이전 / 다음 메모 | `Ctrl+PageUp` · `Ctrl+PageDown` | 메모창 |
| 메모 안에서 찾기 | `Ctrl+F` · `Ctrl+G` | 메모창 |
| 굵게 | `Ctrl+B` | 메모창 |
| 현재 줄 지우기 | `Ctrl+D` | 메모창 |
| 들여쓰기 / 내어쓰기 | `Tab` · `Shift+Tab` | 메모창 |

전역 단축키는 트레이 메뉴의 `단축키 설정`에서 바꿀 수 있다. 메모창 안의 조합은 고정이다.

## 실행

```bash
npm install
npm start
```

`npm start`는 번들을 먼저 만들고 Electron을 띄운다.

`빠른메모 실행.bat`은 번들을 만들지 않고 바로 띄우므로, **clone 직후에는 쓸 수 없다.**
`renderer/bundle/`이 저장소에 없기 때문이다. 한 번이라도 `npm start`나 `npm run bundle`을 돌린 뒤에 쓴다.

### 부팅 확인

```bash
npm run smoke
```

앱을 실제로 띄워 첫 화면까지 살아 있는지 본다. 기능이 올바른지는 보지 않는다.

preload는 sandbox 안에서 돌기 때문에 `electron` 말고 다른 모듈을 `require`할 수 없는데,
이 제약은 코드를 읽어서도 Node로 돌려 봐서도 드러나지 않는다. 게다가 어겼을 때 증상이 조용하다 —
창은 멀쩡히 뜨고 에러도 없이 아무것도 동작하지 않는다. 그 종류의 사고만 잡는 도구다.

## 빌드와 배포

```bash
npm run build
```

`dist/빠른메모.exe` 하나가 나온다 (portable, 설치 불필요).

`빌드 후 배포.bat`은 여기에 더해 실행 중인 앱 종료 → 빌드 → 바탕화면 복사 → 시작프로그램 등록까지 한다.
실제 작업은 `deploy.ps1`에 있다. 배치 파일이 아닌 이유는 `npm`이 콘솔 코드페이지를 UTF-8로 바꿔
배치에 적힌 한글 경로가 그 시점에 깨지기 때문이다.

시작프로그램에 등록되는 바로가기는 `--autostart`를 달고 앱을 부른다.
그러면 로그인 직후 창을 띄우지 않고 트레이에만 올라간다.

## 저장되는 곳

```
%APPDATA%\빠른메모\
├─ notes\
│  └─ 20261016-103045.txt     메모 하나가 파일 하나. 파일명이 곧 id
├─ settings.json              단축키, 즐겨찾기, 조회 전용, 마지막 메모, 창 위치
└─ settings.backup.json       설정이 깨졌을 때 돌아올 지점
```

**파일명이 곧 id**다. `settings.json`의 즐겨찾기·조회 전용 배열과 메모별 단축키가 전부 파일명을 키로 쓴다.
그래서 탐색기에서 메모 파일을 지우거나 이름을 바꿔도 앱이 켜질 때 알아서 정리된다.

## 구조

```
main.js              앱을 켜고 끄는 순서, 모듈 간 배선. 여기서는 아무 일도 하지 않는다
src/main/            메인 프로세스 — 파일 읽기·쓰기, 창, 전역 단축키
src/renderer/        화면 — 편집 창, 목록 패널, 설정 창
src/editor-engine.js CodeMirror를 아는 유일한 파일
shared/              메인과 화면이 함께 쓰는 상수 (IPC 채널 이름 등)
renderer/            HTML과 CSS. bundle/은 esbuild 산출물이라 저장소에 없다
tools/smoke.js       부팅 확인
```

화면 코드는 그대로 로드되지 않는다. esbuild가 세 진입점(`editor.js`, `settings.js`, `preload.js`)을
`renderer/bundle/`로 묶고, 창은 그 번들을 읽는다.

자세한 설계와 고칠 때 주의할 자리는 **`빠른메모_개발자문서.html`** 에 있다.
사용법은 **`빠른메모_사용설명서.html`** 에 있고, 트레이 메뉴에서 바로 열 수 있다.

## 환경

Windows 11 · Electron 44 · 런타임 의존성은 `marked` 하나뿐이다.
